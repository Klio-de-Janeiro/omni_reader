# Исправление остановки на загрузке NumPy

Сообщение «загрузка NumPy не завершилась за 30 с» показывает срабатывание
таймаута приложения. Само по себе оно не устанавливает причину задержки:
медленный импорт, постороннее окружение и зависание DLL различаются по журналу.
По предоставленному сообщению подтвердить конкретную причину на ноутбуке нельзя.

## Применение

1. Закройте Omni через пункт **Выйти из Omni** в трее, чтобы Python освободил DLL.
2. Распакуйте этот ZIP в корень проекта с заменой файлов. Он совместим с этапом 4.
3. Откройте PowerShell в папке проекта и выполните:

```powershell
.\SETUP_VOICE_WINDOWS.ps1
.\START_WINDOWS.cmd
```

Скрипт переустанавливает закреплённые колёса NumPy, SciPy и sounddevice в
`C:\Users\User\Desktop\omni_voice_env`, отдельно проверяет NumPy и затем Silero.
Он не меняет Python/пакеты Whisper, модель Qwen, записи и пользовательские настройки
Omni. Сеть нужна для повторной загрузки пакетов. Python диктофона остаётся:
`C:\Users\User\Desktop\omni_voice_env\Scripts\python.exe`.

Если запускаете установленное приложение, пересоберите его командой
`.\BUILD_WINDOWS.cmd` и установите полученный установщик. Изменение исходников
проекта не обновляет установленный EXE автоматически. Для проверки патча сразу
используйте `START_WINDOWS.cmd`. Готового EXE в архиве нет.

## Что изменилось

- Python диктофона запускается с `-I`: посторонние `PYTHONHOME`, `PYTHONPATH`
  и пользовательские site-packages не подменяют выбранное окружение. Доступны
  штатные пакеты окружения и собственные модули диктофона.
- На импорт NumPy даётся 120 секунд; после него отдельно проверяются вычисления
  и указываются версия/путь библиотеки. Общий предел старта — 300 секунд.
  Ожидание не продлевается повторяющимися сообщениями. Кнопка Stop сохраняет
  возможность принудительно завершить зависший Python.
- Поиск микрофонов использует таймауты по этапам вместо прежних общих 30 секунд.
- Пока этап загрузки не завершён, каждые 15 секунд Python пишет стек в stderr.
  После запуска микрофона эта диагностика отключается. `voice-startup.log`
  содержит этапы, выбранный Python, его окружение и последние 24 КБ stderr.
- Установка использует `--force-reinstall --no-cache-dir`: повторный запуск
  действительно заменяет файлы NumPy, а не оставляет «уже установленный» пакет.
  Torch и Python ONNX Runtime диктофоном не загружаются.

## Отдельная проверка NumPy

В папке проекта можно выполнить:

```powershell
& "$env:USERPROFILE\Desktop\omni_voice_env\Scripts\python.exe" -I -X utf8 -u .\scripts\check-voice-runtime.py --numpy-only --timeout 180
```

При успехе в выводе появится `numpy-cpu` и `Voice environment self-check: OK`.
Здесь не загружаются Silero, Torch или библиотека микрофона. Если проверка
зависает, она завершает дочерний процесс и показывает последний этап/стек.

Если приложение опять остановится, сохраните полный файл
`C:\Users\User\AppData\Roaming\omni-reader-desktop\voice-startup.log` и пришлите
его вместе с выводом этой команды. Если сообщение всё ещё говорит именно о
**загрузке NumPy за 30 секунд**, запущена старая копия приложения: в этом патче
лимит этой фазы — 120 секунд.

## Проверка патча

Проверяются изолированный запуск с заведомо неверными переменными Python,
реальные операции NumPy, холодный импорт длительностью 60 секунд на управляемых
часах, стек искусственно зависшего импорта, принудительная остановка,
ограничение общего времени и работа предыдущих этапов.

На Linux выполнена проверка реальных NumPy 2.2.6 и Silero через sherpa-onnx 1.13.8
в изолированном окружении. `npm test`: 213 тестов, ошибок нет; синтаксис Python
и изменения исходников проверены. Физический микрофон и Windows здесь недоступны;
проверка PortAudio в этой среде остановилась с `PortAudio library not found`.
Поэтому запуск на вашем ноутбуке не считается подтверждённым этой проверкой.

Основа изоляции и диагностики:
[Python isolated mode](https://docs.python.org/3.11/using/cmdline.html#cmdoption-I),
[faulthandler](https://docs.python.org/3.11/library/faulthandler.html).
