# Исправление Windows-сборки Omni 0.3.0

## Применение

1. Закройте Omni и запущенные команды сборки.
2. Распакуйте содержимое патча в корень существующего проекта — папку с `BUILD_WINDOWS.cmd`. Подтвердите замену `BUILD_WINDOWS.cmd` и `desktop/package.json`. Новый `desktop/package-lock.json` также должен оказаться в папке `desktop`.
3. Откройте PowerShell в этой папке и выполните:

```powershell
.\BUILD_WINDOWS.cmd
```

Нужны Windows 10/11 x64, Node.js **22.12.0 или новее**, npm и интернет. Electron 42.1.0 требует Node.js >=22.12.0. Глобальные настройки npm менять и Git устанавливать для этого исправления не нужно.

При успешном завершении файл появится здесь:

```text
release\windows\Omni-Reader-0.3.0-Windows-Setup.exe
```

`npm ci` автоматически заменяет старую папку `desktop/node_modules` зависимостями из нового lock-файла. Другие папки проекта и пользовательские файлы приложение не удаляет.

## Причина и изменения

`electron-builder@26.0.12` использует `app-builder-lib@26.0.12`, далее `@electron/rebuild@3.7.0`, который требует `@electron/node-gyp` по Git-ссылке. В npm 12 загрузка Git-зависимостей по умолчанию запрещена, поэтому возникал `EALLOWGIT`.

- Только для `@electron/rebuild@3.7.0` Git-зависимость заменена через `overrides` официальным опубликованным пакетом `@electron/node-gyp@10.2.0-electron.2` из npm. Это тот же Electron fork, а не подмена обычным `node-gyp`.
- Версии Electron 42.1.0 и electron-builder 26.0.12 сохранены. Добавлен lock-файл с зафиксированными версиями и контрольными суммами; Git-источников в нём нет.
- Сборка использует `npm ci --include=dev`, проверяет Node.js и npm, явно загружает бинарник Electron через его штатный `install.js` и использует этот бинарник при упаковке. В Electron 42 загрузка уже не выполняется через `postinstall`.
- В `allowScripts` разрешён только установочный скрипт точной версии `electron-winstaller@5.4.0`, присутствующей в дереве зависимостей. Проверено: скрипт выбирает и копирует комплектный 7-Zip для архитектуры компьютера. Разрешение всех скриптов или всех Git-зависимостей не включается.
- Автопубликация отключена для команды сборки. Сообщение об успехе выводится только после успешной упаковки и проверки наличия ожидаемого EXE.

Изменены два существующих файла: `BUILD_WINDOWS.cmd`, `desktop/package.json`. Добавлены `desktop/package-lock.json` и эта инструкция. Интерфейс, редакторы, ресурсы документов, Android-проект и код Electron-оболочки не менялись.

## Проверки

Проверено в Linux-среде на Node.js 24.19.0 и **npm 12.0.2**, той же версии npm, что в сообщении об ошибке:

- Исходный `desktop/package.json` воспроизводит точный `EALLOWGIT` с той же Git-ссылкой.
- С исправленным manifest успешно создан lock-файл: 342 записи, ни одного Git-источника.
- Чистая установка `npm ci --include=dev` успешно установила 328 пакетов. Разрешённый установочный скрипт выполнился без блокировки npm.
- `npm ls` подтвердил цепочку с `@electron/node-gyp@10.2.0-electron.2`; CLI electron-builder запускается с версией 26.0.12.
- Windows-бинарник Electron 42.1.0 x64 скачан и распакован штатным установщиком с проверкой контрольной суммы.
- Кросссборка дошла до создания `win-unpacked/Omni Reader.exe` и упаковки NSIS. Первая попытка остановилась на `E_FAIL` Linux-версии 7-Zip при сжатии; это отдельный результат проверки среды, а не повторение `EALLOWGIT`.
- Повторная проверка финальной конфигурации с временным параметром `--config.compression=store` прошла архивацию и остановилась при создании деинсталлятора: в Linux-среде отсутствует Wine. Параметр `compression=store` в проект и CMD не добавлялся; для Windows Wine не требуется.

Запуск самого CMD на Windows, создание финального установщика с настройками по умолчанию и установка на Windows пока не подтверждены. Успешная установка npm-зависимостей не выдаётся за успешную сборку установщика.
