# Исправление запуска Silero: DLL Python ONNX Runtime

Архив содержит этап 3 и исправление запуска диктофона. Он устанавливается
поверх этапа 2 с исправлением запуска Silero или поверх уже установленного
этапа 3. В нём только новые и изменённые исходники, инструкции и тесты;
EXE, модели, Python-окружение и аудиозаписи не включены.

## Причина и исправление

Приведённый стек завершается при импорте `onnxruntime_pybind11_state`, до
загрузки весов Silero и открытия микрофона. Из сообщения нельзя определить
конкретную неисправную зависимость Windows DLL. Увеличение таймаута не
исправляет такой сбой.

Диктофон теперь запускает те же локальные веса Silero 6.2.1 через
`sherpa-onnx==1.13.8` и `sherpa-onnx-core==1.13.8`, как проверка голоса
в этапе 3. Пакеты включают собственные нативные CPU-библиотеки;
Python-пакет `onnxruntime` и его `onnxruntime_pybind11_state` не импортируются.
Torch/TorchAudio и Python-код пакета Silero также не импортируются.

Порог речи применяется в нативной модели. Пауза, предзапись, длина фрагмента,
WAV/JSON и очередь Whisper продолжают использовать настройки диктофона.
Для передачи решений используются короткие 512-сэмпловые кадры и 64 сэмпла
контекста. Нативная модель не копит всю запись; длиной WAV управляет Omni.
Настройки и окружение Whisper, записанные файлы и данные этапа 3 не заменяются.

Установочный скрипт переустанавливает оба CPU-пакета из готовых колёс, обходя
кеш pip. Устанавливать или удалять старый `onnxruntime` вручную не требуется.
Если новый нативный импорт тоже завершится ошибкой, диагностика покажет
его собственное сообщение, фактический Python и этап, а не общий таймаут.

## Установка на ноутбуке

1. Остановите запись и полностью закройте Omni через меню значка в трее.
2. Распакуйте архив в корень исходников с заменой файлов, сохраняя папки.
3. Из этой папки выполните в PowerShell:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\SETUP_VOICE_WINDOWS.ps1 -InstallVCRuntime
   ```

   Скрипт проверяет подпись установщика Microsoft Visual C++ Runtime x64.
   Если он попросит перезагрузку, перезагрузите Windows и повторите команду
   без `-InstallVCRuntime`. Успешный результат: `Voice environment self-check: OK`.
   Самопроверка не включает микрофон и не запускает Whisper.

4. Для функций этапа 3, если модель ещё не установлена, выполните
   `powershell -NoProfile -ExecutionPolicy Bypass -File .\SETUP_SPEAKER_WINDOWS.ps1`.
   Уже загруженная подходящая модель используется повторно.
5. Соберите обновлённое приложение командой `.\Build_windows`.
   Для запуска исходников можно использовать `START_WINDOWS.cmd`.
6. В настройках микрофона проверьте Python:
   `C:\Users\User\Desktop\omni_voice_env\Scripts\python.exe`.
   Обновите микрофоны и начните запись.

Для повторной проверки без установки:

```powershell
& "$env:USERPROFILE\Desktop\omni_voice_env\Scripts\python.exe" -u .\scripts\check-voice-runtime.py --audio --timeout 90
```

Имя движка в успешном ответе: `silero-sherpa-onnx-cpu`.
Если старая программа всё ещё пишет «Загрузка ONNX Runtime для Silero»,
запущен старый EXE: после замены Python-исходников приложение нужно пересобрать.

## Что проверено

Проверены настраиваемый порог, PCM и контекст, сброс после самопроверки,
запуск при намеренно сломанном импорте `onnxruntime`/Torch, сообщение об ошибке
нового CPU-движка, таймаут и остановка зависшего процесса. Проверены тесты
диктофона, очереди Whisper и датасета этапа 3.

Настоящая модель Silero через новый движок прошла самопроверку на CPU в Linux.
Через весь Python-диктофон также записан WAV из тестового аудиопотока:
оригинальный PCM сохранён, созданы WAV/JSON, остановка завершилась штатно.
Импорт onnxruntime/Torch был принудительно запрещён. Микрофон в этом тесте
заменён воспроизведением WAV, а модель Silero и остальной диктофон настоящие.
Проверена доступность пакетов Windows x64 для Python 3.11 и присутствие
собственных DLL в них. Здесь нет Windows и физического микрофона:
загрузку DLL на вашем ноутбуке подтверждает самопроверка из шага 3.
