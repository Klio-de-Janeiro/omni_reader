# Omni Reader — Android release для RuStore

## Причина ошибки магазина

Ранее `BUILD_ANDROID.ps1` выполнял `assembleDebug` и выдавал APK для разработки. Такой APK имеет отладочную подпись и разрешает отладку. Для публикации нужна подписанная сборка `release` с `debuggable=false`.

Обновление меняет стандартную команду сборки на `assembleRelease`, подключает постоянный ключ, проверяет цифровую подпись и отсутствие отладочного флага. Результат: `release\omni.apk`.

Имя пакета: `dev.klio.omni`. Версия: `0.3.0`, `versionCode=4`. Минимальная версия Android: 8.0 (API 26). Целевая версия: API 35.

## Готовый APK

Переданный `omni.apk` — подписанный release APK. Его можно выбрать при загрузке версии в RuStore вместо предыдущего debug APK. В магазин загружается только APK, **не архив ключа подписи**. Модерация и заполнение карточки приложения остаются отдельными этапами; устранение отладочного флага не гарантирует одобрения всего приложения.

## Повторная сборка на Windows

1. Распакуйте `Omni_Android_Release_Patch.zip` в корень существующего проекта, рядом с `BUILD_ANDROID.cmd`, с заменой файлов.
2. Распакуйте `Omni_Android_Signing_Backup.zip` **в тот же корень проекта**, сохраняя структуру папок. Это ключ, которым подписан предоставленный APK, и локальные настройки. Если в проекте уже существует ключ ранее опубликованной release-версии, сохраните и используйте именно его. Не заменяйте существующий ключ новым.
3. Установите Android Studio. В SDK Manager нужны **Android SDK Platform 35** и **Android SDK Build-Tools 35.0.0**. Нужны также Node.js 22.12+ и JDK 17+; скрипт умеет использовать встроенный JDK Android Studio.
4. Запустите в PowerShell из корня проекта:

   ```powershell
   .\BUILD_ANDROID.cmd
   ```

5. После успешного завершения возьмите **`release\omni.apk`** и загрузите его в RuStore.

Если SDK установлен в нестандартную папку, задайте перед запуском `$env:ANDROID_HOME` на её путь. Если JDK расположен отдельно, задайте `$env:JAVA_HOME` на каталог JDK, содержащий `bin\java.exe`.

Ключи и пароли не находятся в общих исходниках. Gradle читает игнорируемый локальный файл `android\keystore.properties`. Отсутствие настроек или неправильная подпись останавливают release-сборку; скрипт не подменяет её debug-сборкой.

Для каждого следующего выпуска, который загружается как обновление, увеличивайте `versionCode` в `android\app\build.gradle`: 5, 6 и далее. `versionName` — отображаемая пользователю версия; её меняйте при выпуске новой версии продукта.

## Хранение ключа

Сохраните `Omni_Android_Signing_Backup.zip` в надёжном личном месте с резервной копией. Архив содержит закрытый ключ и файл с паролем, поэтому не отправляйте его другим людям, не загружайте в GitHub и не прикладывайте к карточке магазина. При следующих сборках используйте тот же ключ: другая подпись нарушит совместимость обновлений с уже установленным приложением.

Пароль указан в локальном `android\keystore.properties` в полях `storePassword` и `keyPassword`; псевдоним ключа — `omni`. Публичный сертификат находится рядом с ключом. Он не заменяет закрытый ключ и не позволяет подписывать обновления.

`SETUP_ANDROID_SIGNING.cmd` нужен **только для создания нового ключа первого выпуска**, если готовой резервной копии нет и приложение ещё не опубликовано. Для предоставленного APK этот шаг пропустите: его ключ уже создан и передан. Утилита не перезаписывает существующие ключи и настройки.

## Если на телефоне установлен прежний debug APK

Debug- и release-версии подписаны разными ключами, поэтому Android обычно не позволяет установить release поверх debug. Сначала экспортируйте важные отредактированные файлы и сохранённые копии из приложения, затем удалите debug-версию и установите `omni.apk`. Удаление приложения очищает его внутреннее хранилище. Исходные файлы во внешних папках удаление приложения не затрагивает.

## Google Play

Для нового приложения Google Play нужен AAB, а не этот APK. Подпись уже настроена; в Android Studio используйте **Build → Generate Signed Bundle / APK → Android App Bundle**, выберите тот же ключ из резервной копии, псевдоним `omni` и конфигурацию `release`. Потребуются также требования Play Console к тестированию, target SDK и карточке приложения. Этот патч предназначен прежде всего для устранения отказа из-за debug APK и публикации в RuStore.

## Содержимое патча

- `BUILD_ANDROID.ps1`: release по умолчанию, проверка APK и результат `omni.apk`.
- `android/app/build.gradle`: подпись из локальных настроек, `debuggable=false`, новый `versionCode`.
- Правила Git, исключающие закрытый ключ и локальные пароли.
- `SETUP_ANDROID_SIGNING.cmd` и `.ps1`: создание ключа первого выпуска, если своего ключа ещё нет.
- Эта инструкция.

APK собран из проекта с ранее реализованными функциями редактора, конвертера и больших файлов. Патч сборки меняет только подготовку выпуска. Если предыдущий патч функций ещё не установлен в исходном проекте, установите его отдельно перед повторной сборкой.

## Проверка переданного APK

- Код Android-хоста скомпилирован Java 17 и преобразован в DEX официальным Android SDK Build-Tools 35.0.0 в режиме release.
- Проверка `apksigner verify` успешна: один подписант, RSA 3072, подписи APK v2 и v3. Это новый ключ выпуска, а не стандартный Android Debug.
- Манифест: `debuggable=false`, `testOnly` отсутствует, пакет `dev.klio.omni`, `versionCode=4`, Android API 26–35 (35 — target, а не максимальная поддерживаемая версия ОС).
- Выравнивание APK и целостность ZIP проверены. В APK есть DEX и локальные ресурсы; закрытый ключ и пароли внутрь не включены.
- SHA-256 файла `omni.apk`: `fc8faead324c94f812cad1503cf538e0b208a23196eb00a8cb3b89fc72c8f672`.

В этой среде Gradle не смог загрузить плагин Android из сетевых репозиториев, поэтому переданный APK собран непосредственно официальными инструментами SDK: AAPT2, javac, D8, zipalign и apksigner. Это подписанный release APK, не debug. Исправленный Windows PowerShell-скрипт здесь не запускался. Запуск приложения на реальном телефоне и весь цикл модерации не проверялись.
