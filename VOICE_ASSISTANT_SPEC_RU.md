# Omni: локальный голосовой помощник для Windows

Версия ТЗ: 1.2. Для Windows реализованы диктофон/VAD, очередь Whisper, инструменты
этапа 3 и этап 4: локальный Qwen, активация «Омни», подтверждение и SQLite.
Качество проверки владельца измеряется пользователем на своих контрольных записях.
Планировщик и системные уведомления остаются в этапе 5.
Android не затрагивается. Инструкция этапа 4: `VOICE_STAGE4_RU.md`.

## Цель и границы MVP

Пользователь явно включает микрофон. Omni продолжает работать при сворачивании,
выделяет речь, распознаёт её локальным Whisper и передаёт текст локальному Qwen.
Первый полезный сценарий полного MVP: создать напоминание голосом, получить
уведомление и отметить выполнение либо прогресс. Дополнительный режим — собирать
проверенные записи собственного голоса для датасета.

Silero VAD отличает речь от тишины/шума, но **не узнаёт владельца**. Функция
«реагировать только на мой голос» требует отдельной проверки диктора. До её
реализации записи имеют статус `captured_unverified` и не являются датасетом
подтверждённого голоса пользователя. Телевизор и чужая речь тоже могут сработать.

Слова из аудио не являются разрешением запускать программы, оболочку, удалять
файлы или отправлять сообщения. В MVP Qwen выбирает только операции с локальными
напоминаниями и режимом сбора записей; исполнение строго проверяет схема команд.

## Архитектура

1. **Electron main**: состояние помощника, доверенный IPC, трей, настройки,
   жизненный цикл, база напоминаний; в следующем этапе планировщик.
2. **Python recorder**: захват микрофона, Silero на CPU, границы фраз, WAV + JSON.
3. **Whisper worker**: локальная модель Small, очередь готовых фраз, русский
   язык по умолчанию, параметры из существующих настроек Whisper.
4. **Qwen adapter**: локальный endpoint, структурированный JSON вместо свободных
   команд. Ollama выбран по умолчанию; доступен совместимый локальный API.
5. **Интерфейс Omni**: управление записью, предложения напоминаний, список задач,
   история прогресса, понятные состояния и ошибки.

Аудио остаётся на диске ноутбука. Интернет нужен для первоначальной установки
зависимостей. Фоновая работа означает запущенный Omni в трее, а не службу Windows.
После завершения Omni и перезагрузки компьютера микрофон выключен.

## Этапы и проверяемый результат

| Этап | Что делаем | Критерий готовности |
|---|---|---|
| 1. Диктофон + VAD | Явный запуск/стоп, микрофон, трей, WAV/JSON, ограничения памяти и диска | При включённом микрофоне фраза сохраняется после паузы; тишина не создаёт WAV; Stop/выход освобождают микрофон; закрытие панели не сбрасывает запись |
| 2. Whisper и активация команд | Последовательная очередь распознавания, текст в Omni, ручное подтверждение; обращение «Омни» для режима команд | Одна фраза даёт один результат; ошибку можно повторить; обычный разговор без обращения не создаёт напоминание |
| 3. Проверка голоса и датасет | Запись эталонов, локальная speaker-verification модель, калибровка, прослушивание и отбор фрагментов | На тестовых записях владельца/других людей измерены ошибки; сомнительные записи остаются на ручной проверке; экспорт WAV + JSONL + исправленные тексты |
| 4. Qwen и напоминания | Адаптер локальной модели, схема намерений, разбор времени, подтверждение, SQLite | «Омни, напомни завтра в 19:00 решить задачи» создаёт предложение с конкретной датой и часовым поясом; неоднозначная дата вызывает уточнение |
| 5. Уведомления и прогресс | Планировщик, Windows-уведомления, перенос, завершение, прогресс, восстановление после перезапуска | Напоминание срабатывает один раз, просроченные видны после запуска; «готово»/«перенеси»/«выполнено 3 из 5» корректно меняют выбранную задачу |

Этапы 1–2 дают рабочий локальный голосовой ввод; напоминания становятся полноценным
MVP после этапов 4–5. Проверку голоса не следует объявлять защитой от воспроизведения
записи: устойчивость к такому сценарию нужно оценивать отдельно.

## Поведение полного MVP

- Состояния: выключено → запуск → слушает → речь → очередь Whisper → предложение
  Qwen → подтверждено/отменено. Ошибки показываются с причиной и возможностью повтора.
- Режимы: «Команды» и «Сбор датасета». Смена режима доступна вручную; голосовое
  переключение требует подтверждения. Qwen не включает скрытую запись.
- В режиме команд после распознавания сохраняется транскрипт и появляется карточка:
  текст задачи, абсолютные дата/время, кнопки подтвердить/исправить/отменить.
- Без даты: спросить когда. «Через час» считается от времени произнесения фразы,
  а не от окончания очереди распознавания. Хранить UTC и исходный часовой пояс.
- Неясные ссылки «отметь это выполненным» уточняют задачу. Голосовой ответ связывается
  с выбранной карточкой, а не со случайным последним напоминанием.
- Qwen возвращает только `create_reminder`, `reschedule_reminder`, `complete_reminder`,
  `update_progress`, `dataset_candidate`, `clarify` или `ignore`.
- Поля намерения: `type`, `source_clip_id`, `title`, `reminder_id`, `due_at`, `timezone`,
  `progress_current`, `progress_total`, `needs_confirmation`, `question`.
  Неизвестные поля/операции, неверные даты и выход за диапазоны отклоняются.
- Прогресс: открыто/в работе/готово/отменено; дополнительно количество или процент.
  Все изменения фиксируются отдельными событиями с временем и источником.
- SQLite: `reminders`, `progress_events`, `audio_clips`, `transcriptions`,
  `notification_deliveries`; идентификаторы клипов предотвращают дубли при повторах.
- Уведомления требуют работающего Omni и разрешённых уведомлений Windows. Во время
  сна/выключенного ноутбука уведомление доставить нельзя: после запуска показать
  пропущенные, не выдавая их за доставленные вовремя.
- Авторестарт Omni и запуск вместе с Windows — отдельная отключаемая настройка
  позднего этапа. Автовключение микрофона не входит в первый этап.

## Параметры первого этапа

- WAV PCM16, 16 кГц, mono; кадр Silero — 512 отсчётов / 32 мс.
- CPU, один поток sherpa-onnx; ONNX-модель из локального пакета
  `silero-vad==6.2.1`. Torch, TorchAudio и Python ONNX Runtime не импортируются.
- Порог начала речи 0,5; порог продолжения ниже на 0,15; настройка 0,1–0,95.
- Пауза окончания: 5000 мс, настройка 200–12000 мс.
- Короткие срабатывания менее 256 мс подтверждённой речи отбрасываются.
- Предзапись и хвост: 1024 мс, настройка 0–2000 мс. Максимальный фрагмент:
  600 с по умолчанию, настройка 30–600 с; длинная речь разбивается на файлы.
- Очередь микрофона: до 64 кадров (~2 с). При переполнении или потере звука запись
  останавливается с ошибкой; тихого пропуска аудио нет.
- Лимит всей папки `sessions`: 500 МБ, настраивается 100–10000 МБ. При достижении
  лимита — остановка, без автоматического удаления предыдущих записей.
- При остатке свободного места менее 100 МБ плюс текущий фрагмент — остановка.
- По умолчанию данные в `voice-recordings` внутри каталога данных Omni. Точный путь
  виден в панели, доступна кнопка открытия и выбор другой папки.
- На каждую сессию своя папка UUID, на фрагмент уникальная пара WAV/JSON.
  JSON содержит дату UTC, длительность, параметры VAD, причину конца и признак
  `speaker_verified: false`. Whisper читает новые фрагменты при включённом авто-
  распознавании; Qwen получает только текст подходящих обращений «Омни».
- Микрофон должен поддерживать mono 16 кГц через выбранный Windows audio endpoint.
  Неподдерживаемый формат сообщает об ошибке; можно выбрать другой endpoint того
  же микрофона. Ресемплинг произвольных устройств отложен до проверки на ноутбуке.

## Производительность и устойчивость

Целевая машина: Intel i3-1305U, 5 ядер / 6 логических процессоров. Для последующей
интеграции Whisper начальный бюджет — 4 потока, Silero — 1. Реальную загрузку CPU,
память, нагрев и скорость Whisper Small измеряем на ноутбуке; текущий патч не
заявляет результатов этих измерений.

Очередь Whisper ограничена 24 фрагментами / 60 минутами, Qwen — 24 командами.
Whisper и Qwen занимают CPU по очереди; исходные WAV/TXT не удаляются при ошибке.
На первом этапе сон Windows останавливает запись; после пробуждения требуется
явное включение. При сбое родительского процесса EOF канала останавливает worker.
При зависании используются таймауты и принудительное завершение worker.

## Проверка первого этапа

Автотесты: сегментация, отбрасывание тишины/коротких щелчков, разделение длинной речи,
корректность WAV/JSON и квоты, отсутствие перезаписи, отмена во время запуска,
одновременные окна, остановка worker, ошибки процесса, доверенный IPC и трей.

Ручная приёмка Windows: включить микрофон, сказать две фразы с паузой, прослушать
WAV; свернуть Omni и повторить; остановить из трея; закрыть и открыть панель;
отключить микрофон; перевести ноутбук в сон; выйти из Omni. Проверить отсутствие
новых записей после остановки, доступность микрофона другим приложениям и
отсутствие дочернего Python после выхода. В этой среде реального микрофона Windows
нет, поэтому эти пункты не считаются выполненными автоматически.
